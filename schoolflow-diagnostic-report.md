## 2. Critical Issues Found

### P0 — Authentication / Password Reset Flow Broken
- File: `server/src/routes/auth.ts` lines 397-470
- Issue: `/auth/reset-password` verifies OTP via `OtpService.verifyOtp` but then attempts to `consumePasswordResetToken` with a dummy token and never actually uses the verified challenge. The password update runs regardless, but the code path contains dead logic and misleading comments.
- Impact: Password reset via Login modal is unreliable and logs confusing audit entries.
- Fix applied: Removed dummy `consumePasswordResetToken` call; challenge consumption is already handled by `verifyOtp`. Password update now follows successful verification.

### P0 — OTP / Email Configuration
- Server env `server/.env`:
  - `OTP_ENABLED=false` → Login OTP step is disabled. OK for dev but audit requires OTP functional.
  - `SMTP_HOST=smtp.gmail.com`, `SMTP_USER=schoolflow.platform@gmail.com` configured.
  - `EMAIL_DEV_EXPOSE_CODE=true` → dev code exposure enabled, acceptable for dev.
- EmailService correctly abstracts provider. `OtpService` is centralized and secure (CSPRNG, hash storage, attempt limits, audit).
- Issue: Client `Login.tsx` still uses legacy `/auth/forgot-password` + `/auth/reset-password` flow. `ResetPassword.tsx` uses correct `/otp/verify` + `/otp/password-reset`. Inconsistent UX.
- Recommendation: Align Login modal to use `/otp/send` → `/otp/verify` flow or keep legacy endpoint fixed (done).

### P1 — Server Port Conflict / Hot Reload
- `server/server.log` shows `EADDRINUSE :::4000` after tsx watch restart.
- Cause: tsx watch restarts server without killing previous process.
- Impact: Development downtime, potential confusion.
- Fix: Ensure process cleanup; consider using `PORT` env consistently. Current config uses 4000 in server/.env but vite proxy expects 4000. Server index reads `process.env.PORT || '4001'`. Mismatch possible.

### P1 — Responsive Regression Suspected
- Layout: `Layout.tsx` uses `lg:pl-[280px]` with fixed sidebar 280px. On 1280px/1366px screens, tables with many columns may overflow horizontally.
- No explicit `overflow-x-hidden` on html/body. DataTable uses `overflow-x-auto` which is correct.
- Sidebar uses `fixed` positioning; mobile drawer works.
- Recommendation: Add global `overflow-x-hidden` to body and ensure containers use `max-w-full`. Verify at 1440/1366/1280/1024/768/390 breakpoints.

### P2 — UI/UX Consistency
- Design system tokens present in `client/src/styles/tokens.css` and `client/src/index.css`.
- No decorative buttons found in initial grep. AGENTS.md rules enforced in code style.
- Motion durations use tokens: FAST 100-150ms, STANDARD 180-250ms.
- Potential issue: `Sidebar.tsx` uses dark hardcoded classes (`bg-dark`, `text-white`, `border-white/10`) while design system uses semantic tokens. May cause mismatch with theme toggle.
